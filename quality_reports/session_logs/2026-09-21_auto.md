## 11:10 — macOS R-CMD-check still failing after `use-public-rspm: true`

**Root cause (upstream, not censobr):** CRAN's macOS builder started shipping `.tgz`
binaries compressed with zstd (r-sig-mac, Sept 2026). pkgdepends/pak only detects
gzip/bzip2/xz, so `pak::lockfile_install()` dies with "Cannot extract ... unknown
archive type" on the first zstd package — `geoarrow_0.4.4.tgz` in our run
(cran.rstudio.com, cloud.r-project.org and mac.cran.dev all serve zstd; only
cran.r-project.org still serves gzip). Tracked as r-lib/pkgdepends#485.

**Why the first fix did nothing:** in setup-r v2.13.0, `use-public-rspm: true`
enables Posit Package Manager on Linux/Windows only; on macOS it applies solely to
Posit-owned orgs. `always` forces PPM on every OS — the workaround the pak
maintainer posted on #485.

**Change:** `use-public-rspm: true` → `always` in `R-CMD-check.yaml` and
`R-CMD-check-CRAN.yaml`. Not committed.
