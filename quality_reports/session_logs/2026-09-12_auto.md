## Note — 2000 household labels

A 2000 block already existed in `add_labels_households()`, covering 12 variables
plus a Sim/Nao sweep. Checked it against the "Households" sheet of the 2000
dictionary and against `2000_households_v0.7.0.parquet`. Three findings:

1. **Dead code (bug).** The 2000 file stores three columns in LOWER case --
   `v1111`, `v1112`, `v1113` -- while the block looked for `V1113` and listed
   `V1111`/`V1112` in `vars_sim_nao`. None of the three ever matched, so the
   entorno variables were never labelled. Fixed by using the lower-case names.
2. **Ignorado was being swallowed.** `v1111`/`v1112` have a code 9 = Ignorado,
   which the `if_else(.x == '1','Sim','Nao')` sweep would have mapped to 'Nao'.
   They now have explicit `case_when()` blocks; removed from the sweep.
3. **Dictionary contradicts the data for v1113.** The sheet lists 1-Sim/2-Nao/
   9-Ignorado, but the data contain code 3 (2,086,499 records). User confirmed
   the questionnaire categories: 1 Total, 2 Parcial, 3 Nao Existe, 9 Ignorado.
   A NOTE comment records the discrepancy.

Added V0222 (n. de automoveis) and V0223 (n. de ar-condicionado), both with the
dictionary's 0-9 category lists -- user asked for these to be labelled even
though they are counts. NOTE: V0222 is int32 and V0223 is string in the source
file, so the comparisons differ per column.

The '.' in v1111/v1112/v1113 (51,326 records, = collective households) is left
unlabelled on purpose.

Verified: all 26 variables of the 2000 block map every observed code, NA counts
unchanged. `test_labels_households.R` passes (26 assertions, 0 failures).

Aside: a corrupted 2010 parquet in the local cache made the first test run error
in `read_households(2010)`; censobr removed and re-downloaded it, second run clean.

### Correction — v1113 dictionary discrepancy resolved

The maintainer fixed the published dictionary. Re-downloaded

corrected version.
