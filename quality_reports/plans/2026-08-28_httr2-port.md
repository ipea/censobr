# Plan — Replace `curl::multi_download()` with httr2

**Status:** COMPLETED 2026-08-28 — adversarial review **dropped the integrity check** (redundant: libcurl already detects partial transfers; broken as written: `as.numeric(NULL)` made the predicate NA so the <5000 fallback never fired; and unsafe under gzip: header 2714 vs disk 7216 would delete good files). Real bug was cleanup, not detection. Port also exposed five dead `data_dictionary()` options returning 404.
**Date:** 2026-08-28
**Scope:** One function, `download_file()` in `R/utils.R`, plus `DESCRIPTION`. No other file calls
`curl::`.

---

## Context

**Why.** The user asked to move the package's single download path from `curl::multi_download()` to
httr2. Every `read_*()` and documentation function routes through `download_file()`
(`R/utils.R:11-66`), so this is the one place that touches the network — a small, well-isolated
change with a large blast radius if it regresses.

**What the port also fixes.** Two open items in `MEMORY.md` are cheap to close here, and the user
approved including them:

1. **Truncation is undetectable today.** `R/utils.R:59` only rejects files under 5000 bytes, so a
   partial download of a multi-MB parquet passes and is cached as valid. Verified against the real
   endpoint: httr2 exposes a `content-length` header that **exactly matches** the bytes written
   (17111950 == 17111950), so an exact integrity check becomes a two-line comparison.
2. **Failed downloads poison the cache.** `req_perform()` leaves a file behind on failure — a 404
   wrote a 9-byte error body to disk in testing. Because `download_file()` returns early when
   `file.exists(local_file) && isTRUE(cache)` (`R/utils.R:33-35`), that leftover is handed back as a
   valid cache hit on the next call and then fails inside `arrow_open_dataset()` as *"File cached
   locally seems to be corrupted"*. This is the mechanism behind the `1991_population` failure seen
   after the machine slept.

**`resume = cache` is dead code — dropping it loses nothing.** The download is only reached when the
file does not exist (nothing to resume) or when `cache = FALSE` (so `resume = FALSE`). It has never
resumed a transfer. Worse, a partial file makes `file.exists()` true, so the early return hands it
back instead of resuming it. Deleting on failure is the correct fix for the case `resume` was
presumably meant to cover.

**Verified httr2 behaviour** (httr2 1.3.0, against the real GitHub release URLs):

| Behaviour | Result |
|---|---|
| `req_perform(path=)` streams to disk, follows GitHub→S3 redirect | ✅ status 200 |
| `content-length` vs bytes on disk | ✅ exact match |
| HTTP 404 | throws `httr2_http_404`, **and leaves a 9-byte file** |
| Connection failure | throws `httr2_failure`; **`req_error()` does NOT suppress it** |
| `req_progress()` | available since httr2 **1.0.0** |

## The change

### 1. `R/utils.R` — replace the download block

Replace the `try(...)` + two failure branches (`:38-63`) with:

```r
  # download file
  req <- httr2::request(file_url)
  if (isTRUE(showProgress)) { req <- httr2::req_progress(req) }

  resp <- tryCatch(httr2::req_perform(req, path = local_file), error = function(e) e)

  # never leave a partial or error-body file behind: download_file() treats an
  # existing file as a valid cache hit, so a bad file would poison the cache
  if (inherits(resp, "error")) {
    if (file.exists(local_file)) { unlink(local_file) }
    if (inherits(resp, "httr2_http")) {
      cli::cli_alert_danger("The file is not available at the source. Please try again later.")
    } else {
      cli::cli_alert_danger("Download failed. Please check your internet connection and try again.")
    }
    return(invisible(NULL))
  }

  # verify the download is complete against the size the server reported
  actual   <- if (file.exists(local_file)) file.info(local_file)$size else NA_real_
  expected <- suppressWarnings(as.numeric(httr2::resp_header(resp, "content-length")))

  incomplete <- is.na(actual) ||
                (!is.na(expected) && actual != expected) ||
                (is.na(expected)  && actual < 5000)

  if (isTRUE(incomplete)) {
    if (file.exists(local_file)) { unlink(local_file) }
    cli::cli_alert_danger("The downloaded file is incomplete. Please try again.")
    return(invisible(NULL))
  }

  return(local_file)
```

Notes:
- **Keeps the two-branch structure and the "each branch states its own cause" principle** established
  in batch 2, and now distinguishes an HTTP error from a connection failure.
- **`is.na(expected)` fallback** preserves the old `< 5000` sanity check for any server that omits
  `content-length`.
- The old messages told the user to run `censobr_cache(delete_file = …)`. That advice is now
  obsolete — the function cleans up after itself — so it is dropped.
- Also removes the latent bug where a genuine `try()` throw left `downloaded_files` undefined and
  `:48` errored with "object not found" (`MEMORY.md`, open item).

### 2. `DESCRIPTION`

Replace `curl (>= 5.0.0),` with `httr2 (>= 1.0.0),`, keeping Imports alphabetical (after `glue`).
No other `curl::` call exists in `R/`; httr2 still pulls curl in transitively.

### 3. `NEWS.md` — one bullet under the existing `# censobr dev`

Downloads now use httr2; an incomplete download is detected against the size reported by the server
and removed instead of being cached.
